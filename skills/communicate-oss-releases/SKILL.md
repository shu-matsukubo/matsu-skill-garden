# 個人OSSの更新の影響を伝える

- 初回リリースはv0.1.0を起点にする。初期開発で破壊的変更を許容する場合も、影響する利用者に変更内容を伝える。
- 変更履歴はリリース単位で整理する。利用者が何が変わり、自分の利用にどんな影響があるかを判断できる粒度にする。
