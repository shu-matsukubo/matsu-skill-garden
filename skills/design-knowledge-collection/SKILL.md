# 安全に継続できるナレッジ収集を設計する

最初に、用途ごとの取得漏れの許容範囲と、後続の整理フローが受け取る入力を確認する。取得漏れを許容する用途では、全情報の取得を必須条件にするより、次の条件で仕組みを比べる。

- 価値のある情報を抽出できる。
- 取得した情報を安全に保存し、既存データを保全できる。
- 後続の整理フローを変更せず接続できる。
- 失敗時に、取得できた範囲と失敗状況を把握できる。

収集側は情報の一時保存を担い、分類・検証・ナレッジ化は後続へ委ねる。完全性だけを理由に複雑な仕組みを追加せず、新しいサービスやサーバーには継続的な管理・保守コストも含めて判断する。取得漏れを許容しない用途では、その要件を維持して設計する。
